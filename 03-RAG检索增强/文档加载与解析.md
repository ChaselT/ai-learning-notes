# 文档加载与解析

## 这是什么/为什么重要

把 PDF、Word、Markdown、HTML 变成**干净的纯文本 + 结构信息**。

听起来是脏活，但第 1 课那张表说过：**RAG 效果差有约 40% 出在解析和分块**。
这是全阶段最枯燥、也最容易被跳过的一课——而跳过它的人，后面调三个月检索参数也救不回来。

**"垃圾进垃圾出"在 RAG 里是字面意义的**：PDF 里的表格被解析成一行没有分隔符的数字，
后续做什么都找不回原来的行列关系。

## 核心内容

### 1. 各格式的难度分级

| 格式 | 难度 | 主要坑 |
|---|---|---|
| **Markdown / TXT** | ⭐ | 几乎没有，读进来就能用 |
| **HTML** | ⭐⭐ | 要剥掉导航栏、页脚、广告等"样板文字" |
| **Word (docx)** | ⭐⭐⭐ | 表格、批注、修订痕迹 |
| **PDF** | ⭐⭐⭐⭐⭐ | **一切苦难的来源**，见下 |

**能拿到 Markdown 就别碰 PDF。** 很多技术文档同时提供两种格式，
优先选结构化的那个——这是最省力的一次优化。

### 2. PDF 为什么是地狱

PDF 本质是**打印指令的集合**，它描述的是"在坐标 (x,y) 画这个字符"，
**根本不存储"段落""表格""标题"这些概念**。所谓解析，就是从一堆字符坐标里反推出结构。

由此产生的典型灾难：

| 症状 | 原因 |
|---|---|
| 表格变成一行乱码 | 单元格边界靠画线表示，文字层没有分隔 |
| 双栏论文串行 | 按坐标从左到右读，把左栏和右栏拼在一起 |
| 段落中间莫名断行 | PDF 里每一行都是独立的文本对象 |
| 页眉页脚混进正文 | 它们和正文在同一个文本层 |
| 扫描件读出空白 | 那是图片，没有文字层，得走 OCR |

### 3. 工具选型

| 工具 | 适合 | 备注 |
|---|---|---|
| `pypdf` | 简单文本 PDF | 最轻，纯 Python |
| `pdfplumber` | **需要提取表格** | 能拿到单元格坐标，表格还原最好 |
| `PyMuPDF (fitz)` | 大批量、要图片 | 快，能导出页面为图片（多模态 RAG 要用） |
| `unstructured` | 混合格式一把梭 | 依赖重，但省心 |
| 视觉模型 OCR | 扫描件、复杂版式 | 你阶段 1 ex09 做过发票 OCR，同一套路 |

**一个务实的组合**：先用 `pdfplumber` 试，表格提不好的页面
再用 `PyMuPDF` 导成图片走视觉模型——你已经有这个能力了。

### 4. 保留结构信息，不要只留纯文本

新手做法：所有文件读成一个大字符串。**这会丢掉最有价值的东西。**

应该保留的元数据：

```python
{
    "text": "年假规则：入职满1年5天……",
    "source": "员工手册.pdf",      # 溯源必需（第 10 课）
    "page": 12,                    # 溯源必需
    "section": "第三章 假期管理",   # 结构感知分块要用（第 5 课）
    "heading_path": ["员工手册", "第三章 假期管理", "3.2 年假"],
}
```

这些元数据的三个用途：

1. **引用溯源**：告诉用户答案出自"员工手册.pdf 第 12 页"
2. **元数据过滤**：只在某个部门的文档里搜（第 6 课）
3. **结构感知分块**：按标题层级切，而不是按字数硬切（第 5 课）

**标题路径（heading_path）尤其值钱**：把它拼进 chunk 文本的开头，
能显著提升检索准确率——因为孤立的"满 1 年 5 天"缺少上下文，
而"员工手册 > 假期管理 > 年假：满 1 年 5 天"语义完整得多。
这是 **contextual retrieval** 的最简版本，下一课细讲。

### 5. 清洗：删掉噪声，但别删过头

必删：页眉页脚、页码、导航栏、"本页空白"、重复的版权声明。

**慎删**：
- 换行符：`\n\n` 是段落边界，是分块的重要信号，别一股脑替换成空格
- 代码块：技术文档里的缩进和空行有意义
- 表格分隔符：别把 `|` 当噪声清掉

**判断标准**：删之前问一句"**这个字符承载信息吗？**"页码不承载，段落换行承载。

### 6. 一个你必须建立的习惯：解析完先人眼看

```python
chunks = parse_pdf("员工手册.pdf")
for c in chunks[:5]:
    print("=" * 60)
    print(c["text"][:500])
```

**每接一种新格式的文档，先打印前几段人眼过一遍。**

这条建议看起来很土，但它是本课最重要的一句话。因为解析失败**几乎不会抛异常**——
它安安静静地给你一堆乱码，你直到评估阶段发现"检索准确率只有 30%"
才回头查，那时已经浪费了两周。

这和你在 [[错题与复盘#E45]] 学到的是同一件事：**看起来跑通了不等于跑对了**，
而且这次连"跑通"的假象都更强——代码全程没报错。

## 动手任务

代码写到 `E:\workspace\AiStudy\phase2-rag\ex04_document_loader.py`（骨架已建好）。

1. 实现 `load_markdown(path)`：读 Markdown，**按标题层级切分**并保留 `heading_path`
2. 实现 `load_pdf(path)`：用 `pdfplumber` 读 PDF，保留 `page` 元数据
3. **找一份带表格的真实 PDF**（技术文档、财报、说明书都行），
   把表格部分的解析结果打印出来，**如实记录它烂成什么样**
4. 针对表格问题至少尝试一种改进（换 `pdfplumber` 的 `extract_table()`、
   或把该页导成图片走视觉模型），记录改进前后的对比
5. 实现清洗函数，去掉页眉页脚，**并说明你怎么判断哪些是页眉页脚**（提示：跨页重复出现的短行）

**完成标准**：三种格式都能读出带元数据的结构化结果；
注释里有表格解析的**失败样本原文** + 改进后的对比；清洗规则有依据不是拍脑袋。
