# 开源选题池

> **目的**：不做玩具 demo。通过每周需求调研积累"真实存在、尚未被好好满足"的需求，到阶段 2/3 时从池子里挑一个做成开源项目——既是练手，也是转行简历的主打作品。
> **产出节奏**：每周日复盘时由 Claude 联网调研一次，新候选追加到「候选清单」，趋势写进「每周调研记录」。
> **决策时点**：① 阶段 2 末（RAG 学完）初筛 2-3 个 → ② 阶段 3 做项目③时定案（优先让项目③本身就是这个开源项目）。

## 评估维度（每个候选按此打分，1-5 分）

| 维度 | 含义 | 权重 |
|------|------|------|
| **需求真实性** | 有人在公开抱怨/求助/悬赏，不是"我觉得有用" | ⭐⭐⭐ 最重 |
| **竞品空隙** | 已有方案不存在或明显不够好（红海直接淘汰） | ⭐⭐⭐ |
| **技术栈契合** | 落在学习路线上（RAG/Agent/MCP/微调），最好能用 Java+Python 双栈做差异化 | ⭐⭐ |
| **可完成度** | 业余时间 1-3 个月能做出可用 v1（能砍到 MVP 的优先） | ⭐⭐ |
| **简历价值** | 面试时能讲出技术深度 + 真实用户 | ⭐⭐ |

**淘汰红线**：需求靠想象 / 已有成熟方案 / 一个人半年做不完 / 纯前端或纯运维（偏离转行方向）。

### C1 · Java/Spring MCP 无状态化迁移 + CI 合规门禁 🔍

- **需求证据**：MCP 2026-07-28 新规范正式发布，Tier 1 SDK 只有 Python/TS/Go/C#，**Java 不在其中**；官方 java-sdk 仓库 31 个 SEP issue 全部 open，无状态化核心几条（#1011 Make MCP Stateless、#1010 Sessionless、#1004 Multi Round-Trip、#1012 弃用 Roots/Sampling/Logging）**milestone 全是「3.x Planning」**——即最新 v2.0.0（2026-06-11）完全不支持新规范；Spring AI 仓库搜 "2026-07-28" 无实质 issue。而客户端侧 Claude 已宣布迁移 → **全世界的 Java/Spring MCP server 现在都是旧规范**
- **竞品空隙**：GitHub 上迁移工具已有 5 个（mcp-stateless-migrator / mcp-migrate / mcp-2026-validator 等），但**全部 ≤1 star、全部 TS/Python、无一个 Java**，多为 demo 级；官方 conformance 套件（★89）对 server 语言无关且已覆盖新规范，但 SDK 集成清单写死在 `known-sdks.ts`，Java 没接
- **技术栈契合**：MCP 新规范本就在阶段 3 必学清单里；Java 侧扫描（`@Tool`/`@McpTool` 注解、session 依赖、AST/字节码分析）是 10 年老本行，Python 侧接官方 conformance harness——**天然双栈**
- **MVP 范围**：Maven/Gradle 插件 + CLI，扫描 Spring AI / java-sdk 工程里的 initialize 握手、`Mcp-Session-Id`、Roots/Sampling 依赖 → 输出迁移 diff → 跑官方 conformance 打分（1-2 个月）
- **风险与对策**：java-sdk 3.x 若发布会削弱"迁移器"价值 → **重心放在 CI 合规门禁**（长期有效：每次提交检查是否符合最新规范），迁移器当引流入口
- **来源**：[SDK betas](https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/) · [java-sdk](https://github.com/modelcontextprotocol/java-sdk) · [conformance](https://github.com/modelcontextprotocol/conformance) · [Claude 迁移公告](https://claude.com/blog/bringing-mcp-2026-07-28-to-claude)

### C2 · Spring Boot REST/注解 → 无状态 MCP Server 自动暴露 🔍

- **需求证据**：跨语言需求已被市场验证——mcpo ★4319、openapi-mcp-generator ★628、mcp-link ★620、higress openapi-to-mcpserver ★275；网关分析明确把"把存量 REST API 虚拟化成 MCP server"列为企业迁移刚需。**Java 侧几乎空白**：唯一像样的 api2mcp4j ★107 且自 2026-03-12 停更（早于新规范）
- **竞品空隙**：Python/TS/Go 已红海，但那些工具吃的是 OpenAPI 文档；**Java 的差异化是直接读 `@RestController`/`@RequestMapping`/Bean Validation 注解 + Actuator 元数据，编译期生成、不依赖手写 spec**——别的语言做不到
- **可完成度 5**：starter + 注解开关 + JSON Schema 生成 + 2026-07-28 stateless 传输，1-2 个月很稳
- **额外好处**：极易在现公司落地（直接达成"在职落地 AI"机制），面试可讲"我司 200 个存量接口一行配置变成 Agent 工具"
- **风险**：Spring AI 官方可能自己做 → 需盯 roadmap
- **来源**：[MCP 网关生态](https://www.arcade.dev/blog/mcp-gateways-runtimes-registries-guide/) · [api2mcp4j](https://github.com/TheEterna/api2mcp4j)

### C3 · Java 侧 LLM/Agent 评测与回归测试框架 🔍

- **需求证据**：Python 侧评测已卷（Ragas/DeepEval/Phoenix/Braintrust/Maxim），公认痛点是"给指标不给发布与监控闭环"；**Java 侧唯一对标物 spring-ai-ragas 只有 5 star 且 2026-04-27 后停更**，Spring AI 自带的只是裸 Evaluator 接口。OTel GenAI 语义约定 v1.41 已定义 agent/workflow/tool/model span，但自动埋点只覆盖 OpenAI/Anthropic/LangChain/LlamaIndex，**无 Java 框架**；且"85% 的 GenAI 部署跑在无可观测状态下"
- **技术栈契合**：JUnit 5 Extension + 断言 DSL + OTel exporter 是最擅长的工程化活；评测指标要用 LLM-as-judge（阶段 1-2 内容）
- **MVP**：faithfulness/context-recall 等核心指标 + JUnit 断言 + CI 报告（1.5-2 个月）
- **风险**：Python 成熟方案可通过 sidecar 复用，说服力打折；比 C1 少了"抢在官方前面"的戏剧性
- **来源**：[spring-ai-ragas](https://github.com/ai-qa-solutions/spring-ai-ragas) · [OTel GenAI 可观测性](https://opentelemetry.io/blog/2026/genai-observability/)

### C4 · MCP Server 安全审计与评分 ❌→ 降级为 C1 模块

- **需求证据很硬**：Equixly 测试显示 **43% 的 MCP server 存在命令注入漏洞**，1899 个 server 中约 5.5% 有 tool poisoning；OWASP 已收录 MCP Tool Poisoning；社区在提"发布前没有公认 checklist"
- **但竞品格局不利**：mcp-scan（Invariant Labs 商业团队）已占位静态扫描；官方 conformance ★89；散兵 mcprobe ★6 / mcp-compliance ★2 / mcp-validation ★7（2025-11 停更）——**大量人试过没人做成，说明单独卖"审计器"拉不到用户**；且安全领域对转行者资历要求高
- **结论**：把"安全 lint + 评分"做成 **C1 的一个 checker 模块**，借 C1 的场景引流
- **来源**：[MCP 安全统计](https://www.practical-devsecops.com/mcp-security-statistics-2026-report/) · [OWASP MCP Tool Poisoning](https://owasp.org/www-community/attacks/MCP_Tool_Poisoning)

## 每周调研记录

### 2026-07-29（首次）

**本周主线：热钱在 Agent 应用层，缺口在 Agent 基础设施层，而 Java 是这层里最空的一格。**

- July 2026 的 GitHub trending 已不是"论文变仓库"，而是 agent + 把 agent 拼起来的胶水（OpenClaw 21 万星、Grok Build、OmniRoute 网关）
- 7-28 落地的 MCP 无状态化规范**一次性作废了全生态的 session 假设**，官方只保证 Python/TS/Go/C# 四个 Tier 1 SDK 跟上，**Java 被结构性甩在门外**（实测确认 Spring AI 与 java-sdk 都还没开工）
- 中文社区的现实提醒值得听：V2EX 上老 Java 转 Agent 的讨论高赞回复是"agent 开发没门槛、就是应用层"——意味着**再写一个 Agent demo 对简历零边际价值**，能拉开差距的恰恰是"给 Agent 生态修工具"这类基建活，而这正是 10 年后端经验唯一无法被应届生复制的地方
- **新增**：C1、C2、C3（🔍）；**淘汰**：C4 降为模块，X1-X4 红海
- **调研员建议路线**：C1 主打（抢新规范时间窗）、C2 作姊妹项目/引流（复用同一套 Spring 元数据分析能力）、C3 备选
- ⚠️ **待解的时间窗矛盾**（下次调研重点跟踪）：C1 的价值来自"官方 Java SDK 还没支持"，但学员要到阶段 3（约 4-5 个月后）才学 MCP。若 java-sdk 3.x 在此之前发布，"迁移器"价值大打折扣。三条应对思路留待决策时权衡：① 把重心放在长期有效的 **CI 合规门禁**；② C1 的 Java 扫描部分**用现有技能可提前动手**（不必等阶段 3）；③ 转向时间敏感度低的 C2
