### E03 · 顶层语句无条件执行
`2026-07-24` · 来源：b01 练习 · #阶段0 #模块

> [!danger] ❌ 当时的写法
> ```python
> message = "hello"
> print(message)          # 顶层先跑一遍
>
> def main():
>     message = "hello"
>     print(message)      # main() 里又跑一遍
>
> main()                  # 直接运行：同样的内容打印两次
> ```

> [!success] ✅ 正确写法
> ```python
> def main() -> None:
>     message = "hello"
>     print(message)
>
> if __name__ == "__main__":
>     main()
> ```

**机制**：模块被加载时（直接运行或被 import）会从上到下**逐条执行所有顶层语句**。规范是顶层只放 import / def / 常量，逻辑收进函数，由 `if __name__ == "__main__"` 触发。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么 `if __name__ == "__main__"` 能防止被 import 时执行逻辑？
> A：直接运行时模块的 `__name__` 是 `"__main__"`；被 import 时是模块自己的名字，条件不成立，守卫内的逻辑不执行。

### E05 · Python 的 `/` 恒为 float，`//` 向负无穷取整
`2026-07-24` · 来源：检验题 · #阶段0 #数据类型

> [!danger] ❌ 当时的写法
> ```python
> print(8 / 2)     # 4.0 —— 期望 Java 式的整数 4
> print(-7 // 2)   # -4  —— Java 的 -7/2 是 -3，两边差 1
> ```

> [!success] ✅ 正确写法
> ```python
> print(8 // 2)        # 4：整数结果用整除 //
> print(int(-7 / 2))   # -3：确实要"向零截断"时显式 int()
> ```

**机制**：`/` 是真除法，**永远返回 float**；`//` 是 floor 除法，**向负无穷取整**。Java 的整数 `/` 向零截断，所以正数时两者一致、负数时相差 1（`-7 // 2 == -4` vs Java `-7/2 == -3`）。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么 `-7 // 2 == -4` 而 Java 里是 -3？
> A：Python `//` 取 floor（向负无穷），Java 向零截断；对负数而言 floor 的结果更小，故差 1。

关联：[[基础01-变量与基本类型]] · 复习打卡：✅⬜⬜

### E06 · float 不存储小数位格式
`2026-07-24` · 来源：b02 练习 · #阶段0 #字符串

> [!danger] ❌ 当时的写法
> ```python
> price = 100.00
> print(price)             # 100.0 —— "两位小数"根本没存进变量
>
> line = "|".join(items)   # 用逗号连接  ← 注释说谎，比没注释更糟
> ```

> [!success] ✅ 正确写法
> ```python
> print(f"{price:.2f}")      # 100.00：小数位在输出时用格式说明符控制
> print(f"{price:>10.2f}")   # 宽度与精度可连写
> ```

**机制**：float 存的只是二进制数值，不携带任何显示格式——`100.00` 和 `100.0` 是同一个数。"保留几位小数"是**字符串化那一刻**的表现，由 `:.2f` 这类格式说明符在输出边界决定。附带教训：注释与代码不符（写"逗号"实为 `"|"`）会主动误导读者。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么"保留两位小数"不能在赋值时完成？
> A：数值与显示是两回事；变量里只有数值，格式只存在于转成字符串的那一刻，所以必须在输出边界用格式说明符表达。

`2026-07-25` · 来源：b03 / b04 练习 · #阶段0 #列表

> [!danger] ❌ 当时的写法
> ```python
> s = [3, 1, 2]
> s = s.sort()    # sort 原地排、返回 None → s 变成 None（灭顶之灾）
>
> tags = {"b", "a"}
> tags.sort()     # AttributeError: 'set' object has no attribute 'sort'
> ```

> [!success] ✅ 正确写法

> ordered = sorted(tags)   # 通吃一切可迭代对象，set 也能排

> [!question]- 🔁 自测（先想清楚再展开）
> Q：Python 为什么让原地方法返回 None 而不是返回 self？
> A：约定"返回 None = 我改的是原对象"，防止误以为拿到了新对象；把副作用和链式取值从 API 层面分开。

### E09 · 区间统一含头不含尾
`2026-07-25` · 来源：b05 真 bug · #阶段0 #控制流

> [!danger] ❌ 当时的写法
> ```python
> for i in range(1, 30):    # 想要 1~30，实际只到 29
>     if i % 15 == 0:
>         print("FizzBuzz")  # 恰好漏掉唯一的 FizzBuzz(30)，输出里一个都没有
> ```

> [!success] ✅ 正确写法
> ```python
> for i in range(1, 31):    # 尾巴 +1
> ```

**机制**：Python 所有区间（range、切片）统一是半开区间 `[start, stop)`——含头不含尾。好处：长度恰为 `stop - start`，相邻区间 `range(a, m)` + `range(m, b)` 无缝拼接。代价：写"到 N 为止"时要默念"尾巴 +1"。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：半开区间的设计换来了什么好处？
> A：`range(a, b)` 的长度恰为 b-a，便于心算；相邻区间在 m 处无重叠、无遗漏地拼接，切片同理。

### E11 · 函数负责算，调用方决定怎么用
`2026-07-26` · 来源：b06 练习 · #阶段0 #函数

> [!danger] ❌ 当时的写法
> ```python
> def describe(name, age):
>     print(f"{name} is {age} years old.")   # 题目要求"返回"，写成了 print
>
> msg = describe("Alice", "25")   # msg 是 None；int 传成 str 也无人拦截
> ```

> [!success] ✅ 正确写法
> ```python
> def describe(name: str, age: int) -> str:
>     return f"{name} is {age} years old."   # 注解让 "25" 在检查期被抓
> ```

**机制**：print 是副作用，结果直接进了终端，函数默认返回 None——调用方拿不到任何东西，无法再拼接、断言、写文件。`return` 才把值交还调用链，"函数负责算、调用方决定怎么用"。附带：`describe("Alice", "25")` 类型传错无人拦截，这正是类型注解存在的意义。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：print 版函数为什么"不可组合"？
> A：值没有回到程序里，只能被人眼看到；调用方拿到的是 None，任何后续处理（拼接、测试断言、落盘）都无从谈起。

### E12 · 护栏要么全护要么不护
`2026-07-26` · 来源：b06 练习 · #阶段0 #函数 #异常

> [!danger] ❌ 当时的写法
> ```python
> def stats(*nums):
>     avg = sum(nums) / len(nums) if nums else 0   # 只给 avg 加了护栏
>     return min(nums), max(nums), avg             # 空输入在 min() 处照样炸
>
> stats()   # ValueError: min() arg is an empty sequence
>           # 且这行"验证用的炸弹"忘了删，脚本必崩
> ```

> [!success] ✅ 正确写法
> ```python
> def stats(*nums):
>     if not nums:          # 前置条件在入口一次性拦截
>         return None
>     return min(nums), max(nums), sum(nums) / len(nums)
> ```

**机制**：护栏防的是"空输入"这**一个**前置条件，而 min / max / 除法全都依赖它——只护一处等于没护。前置条件校验应在函数入口集中完成一次。第二个教训：改完必重跑再交，验证用的炸弹代码交付前必须清理。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么前置条件校验放在函数入口，而不是散在各个运算处？
> A：条件只有一个（非空），入口校验一次即可覆盖所有依赖点；分散护栏必然有遗漏，而且重复代码本身就是坏味道。

关联：[[基础06-函数]] · [[基础08-异常处理]] · 复习打卡：✅⬜⬜

### E14 · property 占据类属性名，别覆盖描述符
`2026-07-26` · 来源：b07 双层 bug · #阶段0 #类

> [!danger] ❌ 当时的写法
> ```python
> class BankAccount:
>     @property
>     def balance(self):
>         return self.balance      # 自己触发自己 → RecursionError
>
>     @balance.setter
>     def balance(self, value):
>         self.balance = value     # 同样无限递归
>
> BankAccount.balance = 100        # 把 property 描述符整个覆盖成 int
> # 此后 setter "不生效"——它已经不存在了
> ```

> [!success] ✅ 正确写法
> ```python
> class BankAccount:
>     def __init__(self, balance):
>         self._balance = balance   # 存储字段用 _balance 与属性名错开
>
>     @property
>     def balance(self):
>         return self._balance
>
>     @balance.setter
>     def balance(self, value):
>         if value < 0:
>             raise ValueError("Balance cannot be negative")
>         self._balance = value
> ```

**机制**：property 对象**占据类属性名** `balance`；实例访问 `self.balance` 经描述符协议转发到 getter/setter。getter 内再写 `self.balance` 会再次进入 getter → 无限递归，所以存储字段必须用 `self._balance` 错开。而 `类名.balance = 100` 是类属性赋值，直接把描述符替换成普通 int——描述符协议不再触发，setter 随之消失。**永远别对类名赋值实例数据。**

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么 `类名.balance = 100` 会让 setter"失效"？
> A：setter 生效的前提是类属性 balance 是 property 描述符；类属性赋值把描述符换成了 int，属性访问退化为普通查找，描述符协议整个不再参与。

关联：[[基础07-类与对象]] · 复习打卡：✅⬜⬜

### E16 · 子类 `__init__` 不自动调用父类
`2026-07-26` · 来源：b07 检验（已实验验证） · #阶段0 #类

> [!danger] ❌ 当时的写法
> ```python
> class Shape:
>     def __init__(self):
>         self.color = "Red"
>
> class Rect(Shape):
>     def __init__(self):        # 漏了 super().__init__()
>         self.name = "Rectangle"
>
> print(Rect().color)   # AttributeError: 'Rect' object has no attribute 'color'
>                       # 构造时静默通过，访问时才炸——炸点远离病根
> ```

> [!success] ✅ 正确写法
> ```python
> class Rect(Shape):
>     def __init__(self):
>         super().__init__()     # 显式调用，父类字段才会挂到 self 上
>         self.name = "Rectangle"
> ```

**机制**：Python 的实例字段是 `__init__` **运行时**动态挂到 self 上的，不是类声明的一部分。子类一旦定义了 `__init__` 就完全接管构造——Java 编译器会自动插入 `super()`，Python 不会。漏调则父类字段从未创建，直到被访问那一刻才 AttributeError。

> Q：为什么错误在"访问 color 时"而不是"构造时"爆出？
> A：Python 不做字段声明检查，字段缺失不构成构造错误；只有属性查找失败的那一刻才暴露——所以这类 bug 的炸点天然远离病根。

### E22 · 透传要成对，retry 别白睡
`2026-07-28` · 来源：装饰器课 · #阶段0 #装饰器

> [!danger] ❌ 当时的写法
> ```python
> def log_call(fn):
>     @wraps(fn)
>     def wrapper(*args, **kwargs):
>         return fn()            # 收了参数却裸调 → 带参函数一调就 TypeError
>     return wrapper
>
> # retry：最后一次失败后仍 sleep → 放弃前白睡 delay 秒才 raise
> for i in range(times):
>     try:
>         return fn(*args, **kwargs)
>     except Exception:
>         time.sleep(delay)      # 没判断还有没有下一次
> ```

> [!success] ✅ 正确写法
> ```python
> def wrapper(*args, **kwargs):
>     return fn(*args, **kwargs)   # "收集 + 摊开"成对出现
>
> except Exception:
>     if i < times - 1:            # 还有下一次才值得睡
>         time.sleep(delay)
> ```

**机制**：三个点——① `*args/**kwargs` 在形参处是**收集**、实参处是**摊开**，成对出现才是透传，且必须用**带参函数**验证（无参函数测不出裸调 bug）；② match/if 多分支逻辑相同、仅字符串不同 = 抽象错位，把差异提成数据，且要留意未命中分支会静默返回 None 吞掉函数；③ retry 睡前先问"还有没有下一次"。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么用无参函数验证不了透传 bug？
> A：`fn()` 裸调对无参函数恰好合法，症状被掩盖；只有带参调用才会让缺失的"摊开"暴露为 TypeError——测试用例必须覆盖会触发差异的输入。

### E28 · `await asyncio.sleep` 让路，`time.sleep` 堵路
`2026-07-29` · 来源：async_fetch 三组对照实验 · #阶段0 #async

> [!danger] ❌ 当时的写法
> ```python
> async def fetch_url(...):

**机制**：`await asyncio.sleep` 把控制权交还事件循环（总耗时 = max(各任务)）；`time.sleep` 是同步调用，协程内没有让出点，整个循环冻结（总耗时 = 3 + 全部任务）。**协程里绝不能放同步阻塞调用**——这就是生产事故"接了 async 框架却在 handler 里用 requests"的原型。

### E29 · async 的准确表述：在 await 点让出，冻结的是整个循环
`2026-07-29` · 来源：阶段0测试 A 卷 Q3/Q8 扣分 · #阶段0 #async #表述

> [!warning] ⚠️ 场景
> 实验数据全对，口头表述掉 4 分——三处说法不准：
> - ❌ "async 等待网络响应时**自动**让出" → 让出只发生在 **await 这个显式让出点**；协程里塞 `time.sleep(3)` 一个字节码都不让（自己的 [[#E28]] 实验即反例）
> - ❌ "requests 是同步库，请求没完成会**一直等待**" → 只说了自己等；真正后果是**整个事件循环冻结、所有任务一起停摆**（4.36s = 3 秒冻结 + 1.36 秒真实工作）
> - ❌ 回答"GIL 下为何 async 仍提升吞吐"时**完全没提 GIL**（而题目问的就是 GIL）

**机制**（面试可直接背的完整表述）：GIL 锁的是"同时执行 Python 字节码"，而 IO 密集任务 99% 的时间不在执行字节码、只在等网卡；async 让这些等待期在**单线程内于 await 点交替推进**，吞吐提升不依赖多核并行，所以 GIL 管不着它。反之，同步阻塞调用没有让出点 → 整个循环冻结。必须用同步库时丢进 `asyncio.to_thread(...)` 隔离到线程池。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：面试官追问"你说 async 会自动让出，那我在协程里写 time.sleep 呢？"——怎么答？

### E30 · `print(e)` 可能打出一行空白——异常记了个寂寞
`2026-07-29` · 来源：阶段0测试 B 卷实测 · #阶段0 #异常 #工程

> [!danger] ❌ 当时的写法
> ```python
> try:
>     res = await client.get(url)
> except Exception as e:
>     print(e)     # 实际输出：一行空白！

> ```python

> Q：什么时候该用 instruction、什么时候必须用 few-shot？

### E40 · system prompt 的两个功能是分离的：角色管"怎么理解"，规则管"要不要答"
`2026-08-03` · 来源：ex06 三级对照实验 · #阶段1 #PromptEngineering #幻觉

> [!warning] ⚠️ 三级对照（只删一个变量，其余不变）
> | 组 | system prompt | 问"今天天气怎么样" |
> |---|---|---|
> | A | 角色 + 任务 + **拒答规则** | ✅ 明确拒答"你的提问与编程无关" |
> | B | 角色 + 任务（**删掉拒答规则**） | ⚠️ **被角色绑架**：把天气问题硬解读成代码评审，编出一个不存在的 `class Weather` 并一本正经地评审 |
> | C | 无 system prompt | ❌ 老实回答天气（跑题但无害） |

**机制**：**角色设定**决定模型**用什么框架理解问题**；**拒答规则**决定它**要不要回答**。缺了后者，前者仍然生效——于是模型用错误的框架强行解读一切。

🚨 **B 组比 C 组危险得多**：C 只是跑题，一眼能看出；**B 保持着专业口吻输出编造内容**——这正是 [[#E32]] 说的"幻觉最危险的形态是穿着专业外衣的错误"。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：给 AI 设定了角色却不写边界，会发生什么？
> A：它不会拒绝越界请求，而是**把请求强行套进角色框架**，产出带专业口吻的胡说。所以写 system prompt 时，**角色设定与边界约束必须成对出现**——只写"你是 X 专家"是不完整的。

### E38 · 性能对照实验：三轮才把变量控住

> [!warning] ⚠️ 三轮修正过程（每一轮都推翻上一轮）
> | 轮次 | 结论 | 被什么推翻 |
> |---|---|---|
> | 1 | "流式总耗时比非流式长" | 两次生成的**内容长度不同** |
> | 2 | "去掉打印后流式快 3 倍" | 两次**实际 token 数不同**（max_tokens 是上限不是固定值） |
> | 3 | token 对齐后：流式快 20% | ✅ 站得住 |

> [!success] ✅ 对齐后的真实数据（均为 completion_tokens=200）
> | 版本 | TTFT | 总耗时 |
> |---|---|---|
> | 流式 + 逐 chunk 打印 | 0.6827s | 1.4589s |
> | 非流式 | 1.0122s | 1.0123s |
> | **流式 + 不打印** | **0.1309s** | **0.8019s** |

2. **`print(flush=True)` 的代价惊人**：0.657 秒 = 总耗时的 45%；TTFT 被从 0.13s 拖到 0.68s（慢 5 倍）。**测量工具影响了被测对象**——生产环境接收方是浏览器，不存在此开销

### E35 · 按"条数"截断上下文根本约束不了成本
`2026-07-31` · 来源：ex02_usage_watch 实测 · #阶段1 #上下文管理 #成本

> [!danger] ❌ 常见写法（笔记里给的示例也是这个）
> ```python
> def trim_history(messages, max_messages=6):
>     system = [m for m in messages if m["role"] == "system"]
>     rest = [m for m in messages if m["role"] != "system"]
>     return system + rest[-max_messages:]   # 只保证"条数"，不保证 token 数
> ```
> **实测自证**（同一次运行内，都是保留 6 条）：
> ```
> 第6轮  prompt_tokens: 1228
> 第7轮  prompt_tokens: 3246   ← 同样 6 条，涨 2.6 倍
> ```
> 原因：第 6 轮模型回了一条 2248 token 的超长回复，它进了窗口。

> [!success] ✅ 正确做法
> 按 **token 预算**截断：用 tiktoken 从最近往前累加，超预算就停，system 永远保留。
> （单条消息本身超预算时还要额外处理——截断它或摘要它。）

**机制**：条数与 token 数没有固定比例，一条消息可以是 10 token 也可以是 2000 token。**"保留最近 N 条"给出的是条数上限，不是成本上限**——你以为设了预算，其实没有任何上限。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：截断策略的收益和代价分别是什么？怎么量化？
> A：收益——输入 token 下降（实测 8 轮省 25%，第 8 轮单轮省 44%，轮次越多省越多）；代价——**丢记忆，而且模型不会告诉你**：问"我第一个问题是什么"，它会忠实回答"它能看到的第一个问题"（实测答成了第 4 轮的问题）。**评估时必须分开看输入/输出 token**——截断只影响输入，把总量混在一起比会得出错误结论。

### E34 · Q4_K_M 不是纯 4 bit，显存会比公式算得大

> 实际权重 16.22 GB —— 低估约 6%

> [!success] ✅ 正确认知
> ```
> Q4_K_M 的 M = Medium，是【混合精度】：
>   重要层（attention 的 V、部分 FFN）用 Q6_K，其余才是 4 bit

### E42 · ValidationError 是逐层暴露的，前一层错误挡住后一层
`2026-08-04` · 来源：ex07 无 schema 对照组 · #阶段1 #结构化输出 #pydantic

> [!danger] ❌ 当时的理解
> ```python
> class Resume(BaseModel):
>     years: int = Field(ge=0, le=50)
>
> # 输入"周八，八十年Java开发经验"，且不把 schema 给模型看
> # 尝试1: {"name":"周八","years_of_experience":80}  → 报 years 字段缺失
> # 尝试2: {"name":"周八","years":80}                → 报 years 超限 (le=50)
> # 尝试3: {"name":"周八","years":50}                → 通过
> #
> # 以为 max_retries=3 是"允许犯 3 个错"——为什么模型第一次不顺手把 80 也改了？

> [!success] ✅ 正确理解
> ```python
> # 重试上限要按"错误层数"估，不是按"错误条数"估

> Q：一次 ValidationError 通过了，能说明数据没问题吗？
> A：不能，只能说明**这一层**没问题。深层约束可能被浅层错误挡着从未执行过。这也是回喂式自我修复必须留足重试次数的原因——每轮只能推进一层。

### E44 · 路径沙箱：必须先规范化再判边界，否则 `..` 直接穿过去
`2026-08-05` · 来源：ex08 read_file 工具 · #阶段1 #FunctionCalling #安全

> [!danger] ❌ 错误定序（判边界在前）
> ```python
> candidate = BASE_DIR / user_path
> candidate.relative_to(BASE_DIR)          # ← 此时 .. 还没解析，纯前缀比较
> real = candidate.resolve(strict=True)    # ← 规范化发生在检查之后
>
> # 实测 BASE_DIR = C:\Users\xxx\AppData\Local
> #      user_path = ..\..\..\..\Windows\System32\drivers\etc\hosts
> # relative_to 检查：通过（组件上确实以 BASE_DIR 开头）
> # resolve 之后   ：C:\Windows\System32\drivers\etc\hosts  → 放行，任意文件读取
> ```

> [!success] ✅ 正确定序：规范化 → 判边界 → 判存在 → 判类型
> ```python
> real = candidate.resolve()        # strict=False：解析 .. 与符号链接，不存在也不抛
> try:
>     real.relative_to(BASE_DIR)
> except ValueError:
>     return "错误: 禁止读取目录外的文件"
> if not real.exists():  return "错误: 文件不存在"
> if not real.is_file(): return "错误: 目标不是文件"
> ```

**机制**：`relative_to()` 做的是**路径组件的前缀比较**，不解析 `..`、不跟随符号链接——所以"边界"只有在 `resolve()` 之后才是真的。

🚨 **`strict=True` 会把存在性检查隐式提前**，制造 oracle：目录外**存在**的文件回"禁止读取"，**不存在**的回"文件不存在"——攻击者拿这个差异就能探测系统文件布局。改用 `strict=False` + 显式 `exists()`，越界请求根本走不到存在性检查。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么不能用 `str(path).startswith(str(BASE_DIR))` 判断"在不在目录内"？
> A：三个都挡不住——① `..` 未规范化；② 符号链接可以指向目录外；③ Windows 大小写与短文件名（`PROGRA~1`）。必须先 `resolve()` 拿到唯一规范路径，再用 `relative_to()` 做结构化比较。

### E45 · "测试通过"不等于"测到了"：两种假绿灯
`2026-08-05` · 来源：ex08 越界拦截验证 · #阶段1 #实验设计 #安全 #测试

> [!warning] ⚠️ 同一个防护，连续踩了两种无效验证
> **假绿灯 A —— 被测代码根本没执行**
> 提问「读取 `C:\Windows\System32\drivers\etc\hosts`」，模型看了 tool description 里"禁止读取目录外文件"这句，**自己就把请求拒了**，`read_file()` 一次都没被调用。日志里看到"越界被拒绝"，实际拦截的是 prompt 不是代码——而 prompt 可以被绕过，代码才是最后一道防线。
>
> **假绿灯 B —— 用例修复前后行为一致**
> | 用例 | 修复前 | 修复后 |
> |---|---|---|
> | `C:\Windows\...`（绝对跨盘） | 禁止读取目录外 | 禁止读取目录外 |
> | `..\..\Windows\...`（穿越到不存在的路径） | 文件不存在 | 文件不存在 |
>
> 两个用例在有漏洞的版本上**同样"通过"**，等于什么都没验证。

**机制**：一个用例只有在**修复前会失败、修复后会通过**时才有验证价值（TDD 的 red-green）。选安全测试用例时要先问一句：**"这条在有漏洞的版本上会返回什么？"**——答不上来就说明用例没选对。

有效用例长这样：相对路径穿越 **且目标文件真实存在**（`..\..\tmp\pyc-strings.txt`）——修复前会放行并读出内容，修复后返回拒绝。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：给 LLM 工具写安全测试时，为什么不能只通过对话验证？
> A：模型可能出于 prompt 里的说明**代劳拒绝**，导致被测代码零执行。安全逻辑必须有**不经过模型的直接函数调用测试**——对话验证的是 prompt，直接调用验证的才是代码。

> 同一次预热，一个指标翻 400 倍，另一个纹丝不动。

**机制**：`load duration` 只统计"权重读进显存"，单独计时，**从不污染 eval rate**——所以冷启动时算出的"生成快 2.9 倍"一直是对的。但**首次推理的额外开销**（CUDA kernel 编译、计算图捕获、视觉编码器初始化）发生在第一次前向传播，被计进了 `prompt eval duration`——**那一列没有任何名字提示你它含热身**。

⚠️ 另一层错误：prompt 只有 15 个 token 时，`rate = 15 / 耗时` 测的是**固定开销**不是吞吐。想测 prefill 吞吐，prompt 至少几百 token。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：看到"小模型比大模型慢 28 倍"，第一反应该是什么？
> A：**怀疑测量，而不是解释现象**。违反物理直觉的数字先当作仪器问题排查——参数量更少却更慢，没有合理机制能支撑。急着为反常数据编解释，是 [[#E46]]（顺着输入 token 下降编出"压缩省钱"）同一个毛病。

### E49 · 仪器精度决定算法：拉长基线求斜率，别拿相邻点做差
`2026-08-07` · 来源：ex10 KV cache 系数测算 · #阶段1 #实验设计 #测量

> [!danger] ❌ 拿相邻低档位做差
> ```text
> num_ctx 4096 → ollama ps 显示 16 GB
> num_ctx 8192 → ollama ps 显示 16 GB
> 差值 0 GB  →  系数 = 0 MB/1K   ← 荒谬
> ```

> [!success] ✅ 取跨度最大的两个同质点求斜率
> ```text
> 16384 (16K) → 17 GB = 17408 MB
> 65536 (64K) → 20 GB = 20480 MB
> (20480 - 17408) / (64 - 16) = 3072 / 48 = 64 MB per 1K
> # 用 32768 做中间点交叉验证，同样得 64 → 线性成立
> ```

**机制**：`ollama ps` 只报到**整数 GB**（2 位有效数字）。低档位之间的真实差值小于四舍五入的粒度，**分子全是噪声**。把基线拉长，分母变大，舍入误差被摊薄。

⚠️ 配套两条：① **求斜率只能用同质的点**——溢出到 CPU 之后表观系数变成 96 MB/1K（分配策略不同），混进去就毁了；② 精度不够时可以**换仪器**：`nvidia-smi` 是 MB 精度，但它统计整卡，要先记空载基线再逐档相减。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：两个测量点算出的差值是 0，能得出"没有影响"吗？
> A：不能。先问**仪器分辨率是多少**——差值小于分辨率时，0 是舍入的产物而非事实。这也是本次能反向验证的原因：19.78（从溢出比例反推）+ 2.2（nvidia-smi 空载实测）≈ 22 GB 标称，两个独立来源闭合才算立住。

关联：[[Ollama本地模型]] · [[#E34]] · 复习打卡：⬜⬜⬜

### E01 · SOCKS 代理下裸 httpx 缺 socksio
`2026-07-24` · 来源：环境搭建 · #通用 #环境

> [!danger] ❌ 当时的写法
> ```python

> ```bash
> uv add "httpx[socks]"   # extras 带上 socksio，代理场景才可用

> Q：为什么这个错误在安装时不报、运行时才报？
