### E03 · 顶层语句无条件执行
`2026-07-24` · 来源：b01 练习 · #阶段0 #模块

> [!danger] ❌ 当时的写法
> ```python
> message = "hello"
> print(message)          # 顶层先跑一遍
>
> def main():
>     message = "hello"
>     print(message)      # main() 里又跑一遍
>
> main()                  # 直接运行：同样的内容打印两次
> ```

> [!success] ✅ 正确写法
> ```python
> def main() -> None:
>     message = "hello"
>     print(message)
>
> if __name__ == "__main__":
>     main()
> ```

**机制**：模块被加载时（直接运行或被 import）会从上到下**逐条执行所有顶层语句**。规范是顶层只放 import / def / 常量，逻辑收进函数，由 `if __name__ == "__main__"` 触发。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么 `if __name__ == "__main__"` 能防止被 import 时执行逻辑？
> A：直接运行时模块的 `__name__` 是 `"__main__"`；被 import 时是模块自己的名字，条件不成立，守卫内的逻辑不执行。

### E05 · Python 的 `/` 恒为 float，`//` 向负无穷取整
`2026-07-24` · 来源：检验题 · #阶段0 #数据类型

> [!danger] ❌ 当时的写法
> ```python
> print(8 / 2)     # 4.0 —— 期望 Java 式的整数 4
> print(-7 // 2)   # -4  —— Java 的 -7/2 是 -3，两边差 1
> ```

> [!success] ✅ 正确写法
> ```python
> print(8 // 2)        # 4：整数结果用整除 //
> print(int(-7 / 2))   # -3：确实要"向零截断"时显式 int()
> ```

**机制**：`/` 是真除法，**永远返回 float**；`//` 是 floor 除法，**向负无穷取整**。Java 的整数 `/` 向零截断，所以正数时两者一致、负数时相差 1（`-7 // 2 == -4` vs Java `-7/2 == -3`）。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么 `-7 // 2 == -4` 而 Java 里是 -3？
> A：Python `//` 取 floor（向负无穷），Java 向零截断；对负数而言 floor 的结果更小，故差 1。

关联：[[基础01-变量与基本类型]] · 复习打卡：✅⬜⬜

### E06 · float 不存储小数位格式
`2026-07-24` · 来源：b02 练习 · #阶段0 #字符串

> [!danger] ❌ 当时的写法
> ```python
> price = 100.00
> print(price)             # 100.0 —— "两位小数"根本没存进变量
>
> line = "|".join(items)   # 用逗号连接  ← 注释说谎，比没注释更糟
> ```

> [!success] ✅ 正确写法
> ```python
> print(f"{price:.2f}")      # 100.00：小数位在输出时用格式说明符控制
> print(f"{price:>10.2f}")   # 宽度与精度可连写
> ```

**机制**：float 存的只是二进制数值，不携带任何显示格式——`100.00` 和 `100.0` 是同一个数。"保留几位小数"是**字符串化那一刻**的表现，由 `:.2f` 这类格式说明符在输出边界决定。附带教训：注释与代码不符（写"逗号"实为 `"|"`）会主动误导读者。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么"保留两位小数"不能在赋值时完成？
> A：数值与显示是两回事；变量里只有数值，格式只存在于转成字符串的那一刻，所以必须在输出边界用格式说明符表达。

关联：[[基础02-字符串]] · 复习打卡：✅⬜⬜

### E08 · `sort()` 原地排序返回 None
`2026-07-25` · 来源：b03 / b04 练习 · #阶段0 #列表

> [!danger] ❌ 当时的写法
> ```python
> s = [3, 1, 2]
> s = s.sort()    # sort 原地排、返回 None → s 变成 None（灭顶之灾）
>
> tags = {"b", "a"}
> tags.sort()     # AttributeError: 'set' object has no attribute 'sort'
> ```

> [!success] ✅ 正确写法
> ```python
> s = sorted(s)            # sorted() 返回新 list
> ordered = sorted(tags)   # 通吃一切可迭代对象，set 也能排
> ```

**机制**：`list.sort()` 是原地变更方法，按 Python 约定**原地修改的方法返回 None**（提醒你它改的是自身）；`sorted()` 是内置函数，复制成新 list 再排，接受任意可迭代对象。set 本身无序，根本没有 sort 方法——要排序，第一反应永远是 `sorted()`。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：Python 为什么让原地方法返回 None 而不是返回 self？
> A：约定"返回 None = 我改的是原对象"，防止误以为拿到了新对象；把副作用和链式取值从 API 层面分开。

### E09 · 区间统一含头不含尾
`2026-07-25` · 来源：b05 真 bug · #阶段0 #控制流

> [!danger] ❌ 当时的写法
> ```python
> for i in range(1, 30):    # 想要 1~30，实际只到 29
>     if i % 15 == 0:
>         print("FizzBuzz")  # 恰好漏掉唯一的 FizzBuzz(30)，输出里一个都没有
> ```

> [!success] ✅ 正确写法
> ```python
> for i in range(1, 31):    # 尾巴 +1
> ```

**机制**：Python 所有区间（range、切片）统一是半开区间 `[start, stop)`——含头不含尾。好处：长度恰为 `stop - start`，相邻区间 `range(a, m)` + `range(m, b)` 无缝拼接。代价：写"到 N 为止"时要默念"尾巴 +1"。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：半开区间的设计换来了什么好处？
> A：`range(a, b)` 的长度恰为 b-a，便于心算；相邻区间在 m 处无重叠、无遗漏地拼接，切片同理。

`2026-07-25` · 来源：b05 风格 · #阶段0 #控制流 #命名

> [!danger] ❌ 当时的写法
> ```python

>
> score = [90, 45, 72]

### E11 · 函数负责算，调用方决定怎么用
`2026-07-26` · 来源：b06 练习 · #阶段0 #函数

> [!danger] ❌ 当时的写法
> ```python
> def describe(name, age):
>     print(f"{name} is {age} years old.")   # 题目要求"返回"，写成了 print
>
> msg = describe("Alice", "25")   # msg 是 None；int 传成 str 也无人拦截
> ```

> [!success] ✅ 正确写法
> ```python
> def describe(name: str, age: int) -> str:
>     return f"{name} is {age} years old."   # 注解让 "25" 在检查期被抓
> ```

**机制**：print 是副作用，结果直接进了终端，函数默认返回 None——调用方拿不到任何东西，无法再拼接、断言、写文件。`return` 才把值交还调用链，"函数负责算、调用方决定怎么用"。附带：`describe("Alice", "25")` 类型传错无人拦截，这正是类型注解存在的意义。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：print 版函数为什么"不可组合"？
> A：值没有回到程序里，只能被人眼看到；调用方拿到的是 None，任何后续处理（拼接、测试断言、落盘）都无从谈起。

### E12 · 护栏要么全护要么不护
`2026-07-26` · 来源：b06 练习 · #阶段0 #函数 #异常

> [!danger] ❌ 当时的写法
> ```python
> def stats(*nums):
>     avg = sum(nums) / len(nums) if nums else 0   # 只给 avg 加了护栏
>     return min(nums), max(nums), avg             # 空输入在 min() 处照样炸
>
> stats()   # ValueError: min() arg is an empty sequence
>           # 且这行"验证用的炸弹"忘了删，脚本必崩
> ```

> [!success] ✅ 正确写法
> ```python
> def stats(*nums):
>     if not nums:          # 前置条件在入口一次性拦截
>         return None
>     return min(nums), max(nums), sum(nums) / len(nums)
> ```

**机制**：护栏防的是"空输入"这**一个**前置条件，而 min / max / 除法全都依赖它——只护一处等于没护。前置条件校验应在函数入口集中完成一次。第二个教训：改完必重跑再交，验证用的炸弹代码交付前必须清理。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么前置条件校验放在函数入口，而不是散在各个运算处？
> A：条件只有一个（非空），入口校验一次即可覆盖所有依赖点；分散护栏必然有遗漏，而且重复代码本身就是坏味道。

关联：[[基础06-函数]] · [[基础08-异常处理]] · 复习打卡：✅⬜⬜

### E13 · 推导式 = 循环 + 收集

### E14 · property 占据类属性名，别覆盖描述符
`2026-07-26` · 来源：b07 双层 bug · #阶段0 #类

> [!danger] ❌ 当时的写法
> ```python
> class BankAccount:
>     @property
>     def balance(self):
>         return self.balance      # 自己触发自己 → RecursionError
>
>     @balance.setter
>     def balance(self, value):
>         self.balance = value     # 同样无限递归
>
> BankAccount.balance = 100        # 把 property 描述符整个覆盖成 int
> # 此后 setter "不生效"——它已经不存在了
> ```

> [!success] ✅ 正确写法
> ```python
> class BankAccount:
>     def __init__(self, balance):
>         self._balance = balance   # 存储字段用 _balance 与属性名错开
>
>     @property
>     def balance(self):
>         return self._balance
>
>     @balance.setter
>     def balance(self, value):
>         if value < 0:
>             raise ValueError("Balance cannot be negative")
>         self._balance = value
> ```

**机制**：property 对象**占据类属性名** `balance`；实例访问 `self.balance` 经描述符协议转发到 getter/setter。getter 内再写 `self.balance` 会再次进入 getter → 无限递归，所以存储字段必须用 `self._balance` 错开。而 `类名.balance = 100` 是类属性赋值，直接把描述符替换成普通 int——描述符协议不再触发，setter 随之消失。**永远别对类名赋值实例数据。**

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么 `类名.balance = 100` 会让 setter"失效"？
> A：setter 生效的前提是类属性 balance 是 property 描述符；类属性赋值把描述符换成了 int，属性访问退化为普通查找，描述符协议整个不再参与。

关联：[[基础07-类与对象]] · 复习打卡：✅⬜⬜

### E16 · 子类 `__init__` 不自动调用父类
`2026-07-26` · 来源：b07 检验（已实验验证） · #阶段0 #类

> [!danger] ❌ 当时的写法
> ```python
> class Shape:
>     def __init__(self):
>         self.color = "Red"
>
> class Rect(Shape):
>     def __init__(self):        # 漏了 super().__init__()
>         self.name = "Rectangle"
>
> print(Rect().color)   # AttributeError: 'Rect' object has no attribute 'color'
>                       # 构造时静默通过，访问时才炸——炸点远离病根
> ```

> [!success] ✅ 正确写法
> ```python
> class Rect(Shape):
>     def __init__(self):
>         super().__init__()     # 显式调用，父类字段才会挂到 self 上
>         self.name = "Rectangle"
> ```

**机制**：Python 的实例字段是 `__init__` **运行时**动态挂到 self 上的，不是类声明的一部分。子类一旦定义了 `__init__` 就完全接管构造——Java 编译器会自动插入 `super()`，Python 不会。漏调则父类字段从未创建，直到被访问那一刻才 AttributeError。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么错误在"访问 color 时"而不是"构造时"爆出？
> A：Python 不做字段声明检查，字段缺失不构成构造错误；只有属性查找失败的那一刻才暴露——所以这类 bug 的炸点天然远离病根。

### E22 · 透传要成对，retry 别白睡
`2026-07-28` · 来源：装饰器课 · #阶段0 #装饰器

> [!danger] ❌ 当时的写法
> ```python
> def log_call(fn):
>     @wraps(fn)
>     def wrapper(*args, **kwargs):
>         return fn()            # 收了参数却裸调 → 带参函数一调就 TypeError
>     return wrapper
>
> # retry：最后一次失败后仍 sleep → 放弃前白睡 delay 秒才 raise
> for i in range(times):
>     try:
>         return fn(*args, **kwargs)
>     except Exception:
>         time.sleep(delay)      # 没判断还有没有下一次
> ```

> [!success] ✅ 正确写法
> ```python
> def wrapper(*args, **kwargs):
>     return fn(*args, **kwargs)   # "收集 + 摊开"成对出现
>
> except Exception:
>     if i < times - 1:            # 还有下一次才值得睡
>         time.sleep(delay)
> ```

**机制**：三个点——① `*args/**kwargs` 在形参处是**收集**、实参处是**摊开**，成对出现才是透传，且必须用**带参函数**验证（无参函数测不出裸调 bug）；② match/if 多分支逻辑相同、仅字符串不同 = 抽象错位，把差异提成数据，且要留意未命中分支会静默返回 None 吞掉函数；③ retry 睡前先问"还有没有下一次"。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么用无参函数验证不了透传 bug？
> A：`fn()` 裸调对无参函数恰好合法，症状被掩盖；只有带参调用才会让缺失的"摊开"暴露为 TypeError——测试用例必须覆盖会触发差异的输入。

### E28 · `await asyncio.sleep` 让路，`time.sleep` 堵路
`2026-07-29` · 来源：async_fetch 三组对照实验 · #阶段0 #async

> [!danger] ❌ 当时的写法
> ```python
> async def fetch_url(...):

> ```python

>     # 总耗时 4.36s，其他请求连开工都被拖到 3 秒后
> ```

**机制**：`await asyncio.sleep` 把控制权交还事件循环（总耗时 = max(各任务)）；`time.sleep` 是同步调用，协程内没有让出点，整个循环冻结（总耗时 = 3 + 全部任务）。**协程里绝不能放同步阻塞调用**——这就是生产事故"接了 async 框架却在 handler 里用 requests"的原型。

### E29 · async 的准确表述：在 await 点让出，冻结的是整个循环
`2026-07-29` · 来源：阶段0测试 A 卷 Q3/Q8 扣分 · #阶段0 #async #表述

> [!warning] ⚠️ 场景
> 实验数据全对，口头表述掉 4 分——三处说法不准：
> - ❌ "async 等待网络响应时**自动**让出" → 让出只发生在 **await 这个显式让出点**；协程里塞 `time.sleep(3)` 一个字节码都不让（自己的 [[#E28]] 实验即反例）
> - ❌ "requests 是同步库，请求没完成会**一直等待**" → 只说了自己等；真正后果是**整个事件循环冻结、所有任务一起停摆**（4.36s = 3 秒冻结 + 1.36 秒真实工作）
> - ❌ 回答"GIL 下为何 async 仍提升吞吐"时**完全没提 GIL**（而题目问的就是 GIL）

**机制**（面试可直接背的完整表述）：GIL 锁的是"同时执行 Python 字节码"，而 IO 密集任务 99% 的时间不在执行字节码、只在等网卡；async 让这些等待期在**单线程内于 await 点交替推进**，吞吐提升不依赖多核并行，所以 GIL 管不着它。反之，同步阻塞调用没有让出点 → 整个循环冻结。必须用同步库时丢进 `asyncio.to_thread(...)` 隔离到线程池。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：面试官追问"你说 async 会自动让出，那我在协程里写 time.sleep 呢？"——怎么答？
> A：那不会让出。让出只发生在 await 表达式处；time.sleep 是同步调用，没有让出点，整个事件循环被冻结、其他任务全部停摆——这正是"用了 async 框架却在 handler 里写同步调用"这类生产事故的原型。

### E30 · `print(e)` 可能打出一行空白——异常记了个寂寞
`2026-07-29` · 来源：阶段0测试 B 卷实测 · #阶段0 #异常 #工程

> [!danger] ❌ 当时的写法
> ```python
> try:
>     res = await client.get(url)
> except Exception as e:
>     print(e)     # 实际输出：一行空白！
> # httpx 的连接/超时类异常 str(e) 常为空字符串 → 排查时毫无线索
> ```

> [!success] ✅ 正确写法
> ```python
> except Exception as e:
>     print(f"{url} failed: {type(e).__name__}: {e!r}")   # 类名 + repr，永远有内容
>     # 工程上更该用 logging.exception(...)，自带堆栈
> ```

**机制**：`str(异常)` 只返回构造时传入的 message，很多库的连接类异常构造时不带 message → 空串；`repr()` 与 `type(e).__name__` 一定有内容。**异常处理的价值不在"没崩"，而在"崩了能查"**。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：`except` 里到底该记什么才够排查？
> A：至少三样——出错的对象（哪个 url）、异常类型（`type(e).__name__`）、异常详情（`repr(e)` 或 `logging.exception` 带的堆栈）。只 print 一个 `e` 可能什么都没有。

关联：[[基础08-异常处理]] · 复习打卡：⬜⬜⬜

### E31 · mypy 说 Success ≠ 没问题（免检区复犯，考试扣 2 分）
`2026-07-29` · 来源：阶段0测试 B 卷第 5 项 · #阶段0 #类型注解 #复犯

> [!danger] ❌ 当时的写法
> ```python
> def timed(fn):          # 参数、返回值全无注解
>     @wraps(fn)
>     async def wrapper(*args, **kwargs):   # 函数体整个进入"免检区"
>         ...
>     return wrapper
> # uv run mypy → Success: no issues found  ← 假绿灯
> ```

> [!success] ✅ 正确写法
> ```python
> from collections.abc import Callable, Coroutine, Awaitable
> from typing import Any
>
> def timed(fn: Callable[..., Awaitable[Any]]) -> Callable[..., Awaitable[Any]]:
>     ...
> ```

**机制**：mypy 默认**不检查无注解函数的函数体**（要全查得开 `--strict` 或 `disallow_untyped_defs`）。所以"mypy 通过"只说明"被检查的部分没问题"，装饰器这类容易漏注解的地方恰恰是盲区。**这是 E25 的第二次复犯——第一次是 `def main():`，这次是装饰器。**

> [!question]- 🔁 自测（先想清楚再展开）
> Q：怎么让 mypy 不再放过免检区？
> A：给每个函数都写注解；或在 pyproject.toml 里开 `[tool.mypy] disallow_untyped_defs = true`，让"没注解"本身成为错误。

### E32 · 幻觉会转移：藏在"看起来很懂"的细节里
`2026-07-31` · 来源：ex01 幻觉实验（学员实测 qwen3.5:27b） · #阶段1 #幻觉 #LLM原理

> [!danger] ❌ 观察到的现象
> 问「介绍 Java 的 `@FastLoop` 注解」（不存在的东西），模型**明确否认了**：
> "标准 JDK 和主流开源库中并不存在名为 @FastLoop 的注解" ✅ —— 看起来很靠谱。
> **但同一段回答里，它顺手编造了真实 API 的细节：**
> ```java
> VectorSpec spec = VectorSpecies.INT_SPEC;      // ❌ 无此类型、无此常量
> IntVector v1 = IntVector.broadcast(spec, val);
> v1.loop(...);                                   // ❌ IntVector 没有 loop() 方法

> [!success] ✅ 正确认知
> ```java
> // 真实的 Java Vector API 写法
> VectorSpecies<Integer> SPECIES = IntVector.SPECIES_PREFERRED;
> ```
> 核对方法：凡是**不常用 API 的具体签名/类型名/归属/版本号**，一律去官方文档验证。

> [!question]- 🔁 自测（先想清楚再展开）
> Q：为什么"模型纠正了我的错误前提"反而是个危险信号？
