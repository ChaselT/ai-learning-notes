# 常用标准库与生态

## 这是什么/为什么重要

这一篇是「日常工具箱」：路径、JSON、HTTP、日志、字符串格式化、推导式。单个知识点都不难，但它们决定你的代码是 Pythonic 还是「Java 味 Python」——后者能跑，但同事一眼看出你是新手，AI 框架源码你也读得费劲。目标：把 Java 的惯用法逐个替换成 Python 惯用法。

## 核心内容

### pathlib：面向对象的路径操作

```python
from pathlib import Path

p = Path("E:/workspace/AiStudy/phase0-python")   # 正斜杠在 Windows 也可用
f = p / "data" / "config.json"                   # 用 / 拼路径（重载了运算符）
print(f.suffix, f.stem)                          # .json  config

f.parent.mkdir(parents=True, exist_ok=True)      # ≈ Files.createDirectories
f.write_text('{"k": 1}', encoding="utf-8")       # 一行写文件
text = f.read_text(encoding="utf-8")             # 一行读文件

for py in p.glob("*.py"):                        # 遍历匹配文件
    print(py.name)
# Java 对比：≈ java.nio.file.Path + Files，但 API 集中在一个类上，无需静态工具类
```

别再用字符串拼路径或 `os.path.join`，新代码一律 pathlib。

### json：标准库序列化

```python
import json

data = {"name": "alice", "scores": [90, 85]}
s = json.dumps(data, ensure_ascii=False, indent=2)   # 对象 → 字符串（≈ Jackson write）
obj = json.loads(s)                                  # 字符串 → dict/list（≈ readValue）
print(obj["name"])
```

注意 `loads` 返回的是原生 dict，没有类型；要带 schema 的解析用 pydantic 的 `model_validate_json`（见[[dataclass与pydantic]]）。

### httpx：现代 HTTP 客户端（类比 OkHttp/RestTemplate）

```python
import httpx

resp = httpx.get("https://httpbin.org/get", params={"q": "ai"}, timeout=10)
resp.raise_for_status()              # 非 2xx 抛异常（≈ RestTemplate 默认行为）
print(resp.json())                   # 直接解析 JSON body

resp = httpx.post("https://httpbin.org/post", json={"prompt": "hi"})  # 自动序列化
```

选 httpx 而不是老牌 requests 的原因：API 几乎一样，但 httpx **同时支持同步和异步**（`AsyncClient`），LLM 应用必然要异步（见[[async异步编程]]）。openai SDK 底层用的就是 httpx。

### logging：别再 print

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s - %(message)s",
)
logger = logging.getLogger(__name__)     # ≈ LoggerFactory.getLogger(getClass())

logger.info("model loaded, tokens=%d", 1024)   # 惰性格式化，同 slf4j 的 {} 占位思想
logger.warning("rate limit close")
```

体系和 slf4j/logback 同构：logger 层级（`__name__` 即模块名，天然分层）、level、handler、formatter。脚本调试用 print 无妨，服务代码一律 logging。

### f-string：字符串格式化

```python
name, score = "alice", 0.9163
print(f"{name} scored {score:.2%}")          # alice scored 91.63%
print(f"{score=}")                           # score=0.9163  调试神器（自带变量名）
print(f"{1234567:,}")                        # 1,234,567
# 忘掉 String.format 和 + 拼接，一律 f-string
```

### 推导式与生成器

Java Stream 的 `filter/map/collect` 链，在 Python 里是一个表达式：

```python
nums = [1, 2, 3, 4, 5, 6]

squares = [n * n for n in nums if n % 2 == 0]        # [4, 16, 36]
# Java: nums.stream().filter(n -> n % 2 == 0).map(n -> n * n).toList()

by_name = {w: len(w) for w in ["ai", "llm", "rag"]}  # dict 推导式
total = sum(n * n for n in nums)                     # 生成器表达式：惰性，不建中间列表

def read_large(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.strip()       # 生成器函数：逐行产出，内存 O(1)
                                     # ≈ Stream 的惰性求值；LLM 流式输出就是生成器模式
```

经验法则：一层循环 + 简单条件用推导式；嵌套两层以上就写回普通 for，可读性优先。

### enumerate / zip / 解包：告别下标循环

```python
langs = ["python", "java", "go"]

for i, lang in enumerate(langs, start=1):    # 要下标时用 enumerate
    print(i, lang)                           # 而不是 for i in range(len(langs))

years = [1991, 1995, 2009]
for lang, year in zip(langs, years):         # 并行遍历两个列表
    print(f"{lang}: {year}")

a, b = b, a                                  # 交换变量，无需临时变量
first, *rest = langs                         # 解包：first="python", rest=["java","go"]

if not langs:                                # 判空：空列表为假值
    print("empty")                           # 而不是 len(langs) == 0
```
