# 基础08-异常处理

## 这是什么/为什么重要

Python 的异常机制和 Java 高度相似（try/catch/finally 换了个拼写），但**文化完全不同**：Python 没有 checked exception，鼓励"先做再捕获"（EAFP），异常在 Python 里是正常的控制流工具而不是罕见的灾难。理解这个文化差异比记语法更重要。

## 核心内容

### 1. try / except / else / finally

```python
try:
    n = int("abc")                 # 这行会抛 ValueError
except ValueError as e:            # except = Java 的 catch
    print(f"转换失败: {e}")         # 转换失败: invalid literal for int() ...
else:
    print("只有 try 没抛异常才执行这里")   # Java 没有 else 子句
finally:
    print("总会执行")               # 总会执行
```

```java
// Java 对照
try {
    int n = Integer.parseInt("abc");   // NumberFormatException
} catch (NumberFormatException e) {
    ...
} finally { ... }
// 差异：Python 多一个 else；异常全是 unchecked，没有 throws 声明
```

### 2. 捕获具体异常类型（别用裸 except）

```python
def safe_div(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        print("除数为 0")
        return None
    except TypeError as e:              # 多个 except 从上往下匹配
        print(f"类型不对: {e}")
        return None

print(safe_div(10, 2))     # 5.0
print(safe_div(10, 0))     # 除数为 0 然后 None
print(safe_div(10, "x"))   # 类型不对: ... 然后 None
```

常见内置异常速查（都继承自 `Exception`）：
- `ValueError`：值不合法（`int("abc")`）
- `TypeError`：类型不对（`"a" + 1`）
- `KeyError` / `IndexError`：dict 键不存在 / 序列下标越界
- `FileNotFoundError`：文件不存在
- `ZeroDivisionError`：除零

一次捕获多种用元组：`except (ValueError, TypeError):`。
**不要写裸 `except:`**，它连 Ctrl+C 都会吞掉；最宽也写 `except Exception:`。

### 3. raise：主动抛出

```python
def set_age(age):
    if age < 0:
        raise ValueError(f"年龄不能为负: {age}")    # raise = Java 的 throw
    print(f"年龄设为 {age}")

set_age(20)          # 年龄设为 20
try:
    set_age(-1)
except ValueError as e:
    print(f"捕获: {e}")     # 捕获: 年龄不能为负: -1

# except 里可以 raise 不带参数：原样重新抛出当前异常（≈ Java 的 throw e）
```

### 4. 自定义异常类

```python
class AppError(Exception):              # 继承 Exception 即可
    """业务异常基类。"""

class InsufficientBalanceError(AppError):
    def __init__(self, balance, amount):
        super().__init__(f"余额 {balance} 不足以支付 {amount}")
        self.balance = balance
        self.amount = amount

try:
    raise InsufficientBalanceError(100, 250)
except InsufficientBalanceError as e:
    print(e)             # 余额 100 不足以支付 250
    print(e.amount)      # 250（异常对象可携带业务数据）
```

和 Java 一样：项目定义自己的异常层级，按基类捕获。

### 5. 异常链：raise ... from ...

```python
def load_config(text):
    try:
        return int(text)
    except ValueError as e:
        raise RuntimeError("配置解析失败") from e    # 保留原因（≈ new RuntimeException(msg, e)）

try:
    load_config("abc")
except RuntimeError as e:
    print(e)                 # 配置解析失败
    print(e.__cause__)       # invalid literal for int() with base 10: 'abc'
```

栈回溯里会显示 "The above exception was the direct cause of..."，排查时因果链完整。即使不写 `from`，except 块里抛新异常也会自动带上下文（"During handling of..."）。

### 6. with 预告：资源自动关闭

```python
with open("demo.txt", "w", encoding="utf-8") as f:   # ≈ Java try-with-resources
    f.write("hello")
# 离开 with 块自动 close，即使中途抛异常
```

`with` 背后是"上下文管理器"协议，文件、锁、数据库连接都支持，详见 [[装饰器与上下文管理器]]。

### 7. EAFP vs LBYL：文化差异（重点）

- **LBYL**（Look Before You Leap，Java 习惯）：先检查再操作。
- **EAFP**（Easier to Ask Forgiveness than Permission，Python 推荐）：直接干，出错再接住。

```python
d = {"name": "Tom"}

# LBYL 风格（Java 味）
if "age" in d:
    age = d["age"]
else:
    age = 0

# EAFP 风格（Python 味）
try:
    age = d["age"]
except KeyError:
    age = 0

# 当然这个例子最 Pythonic 的是：age = d.get("age", 0)
```

EAFP 的理由：检查和操作之间状态可能变化（竞态）；正常路径代码不被 if 打断更清晰；Python 异常开销小，抛异常不可耻。工程直觉：**能用 get/默认值就用；预期中的失败用 try/except；不要写一串防御式 if**。

## 常见困惑

**Q1：没有 checked exception，怎么知道函数会抛什么？**
看 docstring、看源码、看运行时表现。所有异常都是 unchecked，不用 `throws` 声明也不强制捕获。代价是靠文档和测试兜底，好处是没有 Java 那种被迫 catch 再包一层的模板代码。

**Q2：用异常做控制流不是反模式吗？**
在 Java 是，在 Python 不完全是。Python 的 for 循环底层就是靠 `StopIteration` 异常结束的。日常尺度：可预期、高频的分支用条件判断；边界失败用异常，别有心理负担。

**Q3：`finally` 和 `else` 都有，什么时候用 else？**
`else` 放"只有成功才做"的后续逻辑，好处是它里面的异常不会被本 try 的 except 误捕。不确定就先不用 else，把成功逻辑写在 try 后面也行。
