# 基础09-模块与导入

## 这是什么/为什么重要

Java 里"一个文件一个 public 类 + package + import"的组织方式，在 Python 里对应"一个 .py 文件就是一个模块 + 包目录 + import"。再加上那句到处可见的 `if __name__ == "__main__":`，搞懂这一篇，你就能看懂任何 Python 项目的骨架。

## 核心内容

### 1. 一个 .py 就是一个模块

假设有两个文件在同一目录：

```python
# 文件 mymath.py —— 这就是一个模块，不需要任何声明
PI = 3.14159

def area(r):
    return PI * r ** 2
```

```python
# 文件 main.py
import mymath                    # 导入整个模块（按文件名，不带 .py）

print(mymath.PI)                 # 3.14159（用 模块名.成员 访问）
print(mymath.area(2))            # 12.56636
```

```java
// Java 对照：文件名必须等于 public 类名，import 的是类；
// Python 导入的是"文件"，文件里的顶层变量、函数、类都是模块成员
```

### 2. from ... import ... 与 as 别名

```python
from mymath import area, PI      # 只导入需要的名字，用时不带前缀
print(area(2))                   # 12.56636

import mymath as mm              # 模块别名（数据圈惯例：numpy as np、pandas as pd）
print(mm.PI)                     # 3.14159

from mymath import area as circle_area   # 成员也能起别名，防止重名
print(circle_area(1))            # 3.14159
```

```java
// Java 对照：import static com.x.MyMath.area; ≈ from mymath import area
// 避免 from mymath import *（≈ Java 的 .*，污染命名空间，社区不推荐）
```

### 3. `if __name__ == "__main__":` 是什么（必须讲透）

Java 的程序入口是固定签名的 main 方法；Python 脚本没有强制入口——文件从上到下直接执行。问题来了：**模块被 import 时，它的顶层代码也会执行一遍！**

```python
# 文件 mymath.py
PI = 3.14159

def area(r):
    return PI * r ** 2

print("mymath 被加载了")          # 顶层代码：import 时也会打印，通常是不想要的副作用
```

Python 的机制：每个模块有个内置变量 `__name__`——
- 直接运行这个文件（`uv run mymath.py`）时，`__name__` 是 `"__main__"`；
- 被别的文件 import 时，`__name__` 是模块名 `"mymath"`。

于是惯用写法：

```python
# 文件 mymath.py（正确版本）
PI = 3.14159

def area(r):
    return PI * r ** 2

def main():
    print("自测：", area(2))      # 自测/演示代码放这里

if __name__ == "__main__":        # 只有直接运行本文件时才成立
    main()

# uv run mymath.py     → 输出 "自测： 12.56636"
# main.py 里 import mymath → 什么都不打印，只是拿到函数定义
```

```java
// Java 对照：public static void main(String[] args) 是 JVM 指定的入口；
// Python 这行 if 就是"手工版的 main 方法开关"——同一个文件既能当库被 import，又能当脚本直接跑
```

### 4. 标准库导入 vs 第三方包

标准库：Python 自带，直接 import，无需安装：

```python
import math
import random
import json
from datetime import date

print(math.sqrt(16))                    # 4.0
print(random.randint(1, 6))             # 1~6 随机整数
print(json.dumps({"name": "Tom"}))      # {"name": "Tom"}
print(date.today())                     # 2026-07-24
```

第三方包：要先安装进项目环境（本项目用 uv 管理，≈ Maven 依赖）：

```
uv add requests        # ≈ 在 pom.xml 加一个 dependency（写入 pyproject.toml）
```

```python
import requests                          # 安装后才 import 得到
r = requests.get("https://httpbin.org/get")
print(r.status_code)                     # 200
```

区分技巧：能不能直接 import 报不报 `ModuleNotFoundError`。标准库清单与常用第三方生态见 [[常用标准库与生态]]，uv 用法详见 [[uv与项目管理]]。

### 5. 包（package）与 __init__.py 简介

模块多了就用目录组织，带 `__init__.py` 的目录就是一个包（≈ Java 的 package 目录）：

```
myproject/
├── main.py
└── utils/
    ├── __init__.py      # 有它这个目录就是包（可以是空文件）
    └── text.py          # 里面定义了 clean() 函数
```

```python
# main.py 里
from utils.text import clean     # 用点号走目录层级，≈ com.x.utils.Text
from utils import text
print(text.clean(" hi "))
```

要点：
- `__init__.py` 通常留空即可；也可在里面做"导出聚合"（`from .text import clean`），让用户直接 `from utils import clean`。
- 包内互相引用可用相对导入：`from .text import clean`（点 = 当前包）。
- Java 的 package 声明写在文件头，Python 的包结构完全由目录决定，文件里不写。

## 常见困惑

**Q1：为什么 import 我自己的模块报 ModuleNotFoundError？**
Python 按 `sys.path`（含当前运行目录）找模块。最常见原因：你不在项目根目录运行，或文件不在搜索路径里。习惯：始终从项目根目录 `uv run xxx.py`。

**Q2：循环导入（a import b，b import a）怎么办？**
和 Java 循环依赖类似，是设计信号。解法：把共用的东西抽到第三个模块；或把 import 挪进函数内部延迟加载。入门阶段遇到先记住"抽公共模块"。

**Q3：`import mymath` 和 `from mymath import area` 该选哪个？**
小分歧，通用建议：模块名短、成员用得少 → `from x import y` 更清爽；成员多或有重名风险 → `import x` 保留前缀更清晰。标准库大模块（math、json）习惯整模块导入。
