# 基础07-类与对象

## 这是什么/为什么重要

Python 也是面向对象语言，class 的概念你全懂，但**写法差异极大**：`self` 要显式写、构造器叫 `__init__`、没有 private 关键字、getter/setter 变成了 `@property`。这一篇专治 Java 工程师看 Python 类时的各种别扭。

## 核心内容

### 1. 最小的类：class + __init__ + self

```python
class User:
    def __init__(self, name, age):    # 构造器，new 的时候自动调用
        self.name = name              # self.name 是实例属性，赋值即定义
        self.age = age

    def greet(self):                  # 实例方法：第一个参数必须是 self
        return f"我是 {self.name}，{self.age} 岁"

u = User("Tom", 25)                   # 没有 new 关键字！类名直接调用
print(u.greet())                      # 我是 Tom，25 岁
print(u.name)                         # Tom（属性默认公开，直接访问）
```

```java
// Java 对照
public class User {
    private String name;              // Java 要先声明字段
    public User(String name, int age) {
        this.name = name;             // this 隐式存在；Python 的 self 必须显式写
    }
    public String greet() { return "我是 " + name; }
}
User u = new User("Tom", 25);
```

### 2. self 到底是什么（重点讲透）

`self` 就是 Java 的 `this`，只是 Python 要求**显式写在参数表第一位**：

```python
class Counter:
    def __init__(self):
        self.n = 0

    def incr(self):
        self.n += 1       # 访问实例属性必须带 self.，漏写 self.n 就成了局部变量

c = Counter()
c.incr()                  # 语法糖：等价于 Counter.incr(c)
Counter.incr(c)           # 显式写法，说明 self 就是被传进来的实例本身
print(c.n)                # 2
```

理解要点：
- `c.incr()` 时，Python 自动把 `c` 作为第一个参数传给 `incr`，接收它的形参习惯上命名为 `self`（不是关键字，纯约定）。
- 定义时写 `def incr(self)`，调用时写 `c.incr()` 不传 self——"定义多一个、调用少一个"，适应几天就自然了。

### 3. 实例属性 vs 类属性

```python
class Dog:
    species = "Canis"             # 类属性：所有实例共享（≈ Java static 字段）

    def __init__(self, name):
        self.name = name          # 实例属性：每个实例各自一份

d1 = Dog("旺财")
d2 = Dog("小黑")
print(d1.species, d2.species)     # Canis Canis（共享）
print(Dog.species)                # Canis（也可通过类名访问）
d1.name = "大旺"
print(d1.name, d2.name)           # 大旺 小黑（互不影响）
```

坑：`d1.species = "X"` 不会改类属性，而是给 d1 创建一个同名**实例属性**遮住它。要改共享值请写 `Dog.species = "X"`。

### 4. 继承与 super()

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."

class Dog(Animal):                       # 括号里写父类（≈ extends）
    def __init__(self, name, breed):
        super().__init__(name)           # 调用父类构造器（≈ super(name)）
        self.breed = breed

    def speak(self):                     # 直接重写，无需 @Override 注解
        return f"{self.name}: 汪汪"

d = Dog("旺财", "土狗")
print(d.speak())                         # 旺财: 汪汪
print(isinstance(d, Animal))             # True（≈ instanceof）
```

### 5. __str__ 与 __repr__（类比 toString）

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __str__(self):                   # print() 时用，给人看
        return f"({self.x}, {self.y})"

    def __repr__(self):                  # 调试/容器内显示时用，给开发者看
        return f"Point(x={self.x}, y={self.y})"

p = Point(1, 2)
print(p)              # (1, 2)               ← 用 __str__
print([p])            # [Point(x=1, y=2)]    ← 容器里用 __repr__
```

只写一个的话优先写 `__repr__`（`__str__` 缺省时会退回用它）。这类 `__xx__` 方法叫"魔法方法/dunder"，`len()`、`in`、`+` 背后都是它们。

### 6. @property：Pythonic 的 getter/setter

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius        # 前缀单下划线 = "内部使用"的约定（非强制）

    @property
    def radius(self):                # getter：访问时像字段一样不用括号
        return self._radius

    @radius.setter
    def radius(self, value):         # setter：赋值时自动触发校验
        if value <= 0:
            raise ValueError("半径必须为正")
        self._radius = value

    @property
    def area(self):                  # 只读计算属性
        return 3.14159 * self._radius ** 2

c = Circle(2)
print(c.radius)      # 2         （像字段，实际走 getter）
c.radius = 3         # 走 setter
print(f"{c.area:.2f}")   # 28.27
# c.radius = -1      # ValueError: 半径必须为正
```

```java
// Java 对照：c.getRadius() / c.setRadius(3)
// Python 风格：先直接用公开属性，需要校验/计算时再改成 @property，调用方代码不用变！
// 所以 Python 不写防御性的 getter/setter 模板代码。
```

### 7. 没有 interface / abstract 强制怎么办

Python 靠"鸭子类型"：不看你声明了什么接口，只看你有没有这个方法。需要强约束时有 `abc.ABC`（抽象基类）和 `Protocol`（结构化接口，更接近 Go 的 interface），入门阶段知道存在即可，详见 [[类型注解与typing]] 与 [[Python与Java核心差异]]。

## 常见困惑

**Q1：为什么每个方法都要手写 self，不嫌烦吗？**
"显式优于隐式"是 Python 设计哲学。好处：一眼区分实例方法与普通函数，`Class.method(obj)` 的等价形式也让方法本质（就是第一个参数为实例的函数）非常透明。

**Q2：没有 private，怎么封装？**
约定优于强制：单下划线 `_x` 表示"内部实现，请勿外部使用"，IDE 和 reviewer 会尊重它；双下划线 `__x` 会触发名称改写（更难被外部访问）。Python 社区的共识是"我们都是成年人"。

**Q3：字段不用先声明，__init__ 里随手 self.x = ... 会不会太乱？**
会有点，所以正式代码常配合类型注解在类头声明 `name: str`，或直接用 `@dataclass` 自动生成 `__init__`/`__repr__`，见 [[dataclass与pydantic]]。
