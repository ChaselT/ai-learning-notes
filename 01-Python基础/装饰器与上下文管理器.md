# 装饰器与上下文管理器

## 这是什么/为什么重要

装饰器（decorator）长得像 Java 注解（`@xxx`），但本质完全不同：**注解只是元数据，靠框架反射生效；装饰器是普通函数，直接包裹并替换目标函数**——相当于把 AOP 的切面逻辑用几行代码写出来。上下文管理器（`with`）则对应 try-with-resources。FastAPI 的路由（`@app.get`）、LangChain 的工具注册（`@tool`）、pydantic 的校验器，全是装饰器语法，不懂它就看不懂 AI 框架代码。

## 核心内容

### 前提：函数是一等公民

```python
def shout(text: str) -> str:
    return text.upper()

f = shout                 # 函数可以赋值
def apply(fn, arg): return fn(arg)
print(apply(shout, "hi"))  # HI —— 函数可以当参数传递
```

Java 里要靠 `Function<String, String>` 接口 + lambda 才能表达；Python 里函数本来就是对象（见[[Python与Java核心差异]]）。

### 台阶一：函数还能"在函数里定义 + 被返回"

这是装饰器唯一的新积木——**造函数的函数**：

```python
def make_greeter(name):
    def greet():                  # 在函数内部定义函数
        print(f"你好, {name}")     # 内层能用外层的变量（闭包）
    return greet                  # 把这把"新枪"返回出去，不开枪

g = make_greeter("朋友")   # g 接住内部造的枪
g()                        # 你好, 朋友 —— 现在才开枪
```

看懂这段，装饰器你已经会 90%。

### 台阶二：手工改装——装饰器的原形（先不用 @）

需求：给任意函数加计时，**不改它的源码**：

```python
import time

def timed(func):                       # 收进来一把原枪
    def wrapper():                     # 造一把改装枪
        start = time.perf_counter()    #   工序 A：先记时间
        result = func()                #   中间照常开原枪
        print(f"耗时 {time.perf_counter() - start:.4f}s")  # 工序 B：报耗时
        return result
    return wrapper                     # 改装枪还回去

def slow_task():
    time.sleep(1)
    print("任务完成")

slow_task = timed(slow_task)   # ★ 改装版顶替原名！
slow_task()                    # 任务完成 / 耗时 1.0012s
```

盯住 ★ 行：`timed(slow_task)` 返回 `wrapper`，赋值回原名。**此后谁调 `slow_task()`，执行的都是 wrapper**——原函数被包在里面，进出多了两道工序。

### 台阶三：`@` 只是 ★ 那行的语法糖

```python
@timed                 # 100% 等价于：slow_task = timed(slow_task)
def slow_task():
    ...
```

没有新机制。`@timed` = "定义完立刻送去改装、用原名接收改装版"的简写。

**时间线（关键认知）**：改装动作（`timed(...)` 这次调用）发生在 **`def` 执行的那一刻，只发生一次**；之后**每次调用**走的都是 wrapper。"定义时改装一次，调用时次次过安检"。

Java 对照：Spring 的 `@Transactional` 就是容器帮你做的这件事——把方法包进代理，调用前开事务、调用后提交。**Python 装饰器 = 不需要框架和动态代理的手工 AOP**。

### 标准版装饰器（补两个零件：@wraps + 参数透传）

```python
import time
from functools import wraps

def timed(fn):
    @wraps(fn)                       # 保留原函数的 __name__/__doc__，必写！
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = fn(*args, **kwargs)
        print(f"{fn.__name__} took {time.perf_counter() - start:.4f}s")
        return result
    return wrapper

@timed                               # 等价于 slow_add = timed(slow_add)
def slow_add(a: int, b: int) -> int:
    time.sleep(0.1)
    return a + b

print(slow_add(1, 2))   # slow_add took 0.1001s  →  3
```

Java 对比：这就是一个方法级 Around advice，但不需要 Spring 容器、不需要代理对象——`@timed` 就是一次普通的函数调用。`*args, **kwargs` 表示透传任意位置参数和关键字参数（≈ `Object[] args` + 具名参数 Map）。

漏写 `@wraps` 的后果：被装饰函数的 `__name__` 变成 `"wrapper"`，调试和文档全乱。

### 带参数的装饰器（三层嵌套）

```python
from functools import wraps

def retry(times: int):               # 第一层：接收装饰器参数
    def decorator(fn):               # 第二层：接收被装饰函数
        @wraps(fn)
        def wrapper(*args, **kwargs):   # 第三层：实际执行
            for i in range(times):
                try:
                    return fn(*args, **kwargs)
                except Exception as e:
                    print(f"attempt {i + 1} failed: {e}")
            raise RuntimeError(f"{fn.__name__} failed after {times} tries")
        return wrapper
    return decorator

@retry(times=3)                      # ≈ Spring Retry 的 @Retryable(maxAttempts = 3)
def flaky_api() -> str:
    import random
    if random.random() < 0.7:
        raise ConnectionError("timeout")
    return "ok"
```

调 LLM API 时重试装饰器是标配（生产上多用 `tenacity` 库，原理相同）。看到 `@app.get("/users")` 时你应该能反应过来：`app.get("/users")` 先执行，返回真正的装饰器。

### 上下文管理器：with ≈ try-with-resources

```python
with open("data.txt", "w", encoding="utf-8") as f:
    f.write("hello")
# 离开 with 块时自动 close，即使抛异常
# Java: try (var f = new FileWriter("data.txt")) { ... }
```

协议：实现 `__enter__`（进入时调用，返回值绑定给 `as` 变量）和 `__exit__`（离开时调用，负责清理）的对象都能用于 `with`——又是鸭子类型，不需要实现 `AutoCloseable` 接口。

### 用 contextlib 快速自定义

写类太重，`@contextmanager` 让你用生成器函数定义上下文管理器：

```python
from contextlib import contextmanager
import time

@contextmanager
def timer(label: str):
    start = time.perf_counter()
    try:
        yield                        # yield 之前 ≈ __enter__，之后 ≈ __exit__
    finally:
        print(f"{label}: {time.perf_counter() - start:.4f}s")

with timer("load model"):
    time.sleep(0.2)                  # load model: 0.2001s
```

AI 工程常见用法：数据库 session、LLM 客户端生命周期（FastAPI 的 lifespan）、临时切换配置、计时与埋点。
