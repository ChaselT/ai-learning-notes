# 阶段 1 测试：LLM 应用开发

> 完成 [[02-LLM应用开发-MOC]] 全部笔记和项目①（CLI 智能助手）后进行。笔试闭卷；实操可查官方文档但不能用 AI 生成代码。
> **批改方式**：做完后把答案和代码发给 Claude，说「批改阶段1测试」。总分 100，**≥80 分进入阶段 2**；不达标复习后换题重考。

## A 卷·笔试（40 分，每题 5 分，预计 30 分钟）

1. 为什么同一个问题问两次，LLM 可能给出不同答案？哪个参数能让输出更稳定？
2. 「多轮对话」在 Chat Completions API 层面是怎么实现的？这带来什么成本问题？
3. 中文和英文哪个更费 token？大概差多少？这对你设计 prompt 有什么影响？
4. temperature=0.2 和 top_p=0.3 同时设置是好做法吗？为什么？
5. 流式输出解决的核心体验问题是什么？SSE 和 WebSocket 相比，为什么 LLM 场景多用 SSE？
6. 写出 Function Calling 的完整消息流转顺序（从用户提问到最终回答，标出每步的 role）。
7. 模型返回的 JSON 偶尔缺字段或格式错误，生产系统里你会怎么兜底？（至少两层）另外：调用返回 429、超时、400 三种错误，哪些该重试、哪些不该，为什么？
8. `qwen3.5:27b` 的 Q4 量化版大约占多少显存（先用公式算）？你的 22G 显存跑它时还能留多少余量给 KV cache？为什么 `qwen3.5:35b` 不建议在这台机器上跑？

## B 卷·实操（60 分，预计 90 分钟）

**题目：结构化情报助手**。在 `E:\workspace\AiStudy\phase1-llm-api\exam_intel_bot.py` 实现一个命令行工具：

1. （15 分）定义 pydantic 模型 `NewsDigest`：`title: str`、`summary: str`（≤50字）、`sentiment: Literal["正面","中性","负面"]`、`keywords: list[str]`（3-5个）
2. （20 分）实现两个工具供模型调用（Function Calling）：`read_local_file(path)` 读取本地文本、`word_count(text)` 统计字数；模型需要能自主决定调用哪个
3. （15 分）用户输入一段新闻文本或文件路径后：模型（本地 Ollama 或任意 API 均可）分析并以**结构化输出**返回 `NewsDigest`，解析失败自动重试一次
4. （10 分）最终回答用**流式输出**打印到终端（摘要部分逐字出现）

**加分项（+10，可抵扣失分）**：传入一张新闻截图，用视觉模型走同样的流程（多模态）。

**评分点**：消息流转正确、异常与重试处理（超时/重试参数配置 + 按异常类型分支）、密钥不硬编码、模型名走环境变量、代码结构清晰（工具定义/调用循环/输出分层）。
