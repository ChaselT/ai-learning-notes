# 结构化输出

## 这是什么/为什么重要

LLM 默认输出自然语言，但程序消费不了"好的，以下是为您提取的信息：…"这种话。结构化输出就是让模型稳定产出**可解析、可校验的 JSON**，类比接口开发：前后端约定 DTO，而不是传一段散文。这是 LLM 从"聊天玩具"变成"系统组件"的分界线。

## 核心内容

### 1. 为什么生产系统必须结构化输出

- 下游代码要 `data["city"]`，不能靠正则从散文里抠字段
- 可校验：字段缺失/类型错误能在边界处立即发现，而不是污染下游
- 可测试、可监控：解析失败率是一个能报警的指标

裸问 LLM 要 JSON 的常见翻车：外面包了 ```json 代码块、多了一句"以下是结果"、字段名随机变化、值类型不稳（"25" vs 25）。所以需要 API 级保证 + 客户端校验双保险。

### 2. JSON mode（response_format）

`response_format={"type": "json_object"}` 让 API 保证输出是**合法 JSON**（但不保证符合你的 schema）：

```python
import json, os
from openai import OpenAI

client = OpenAI(api_key=os.environ["DEEPSEEK_API_KEY"],
                base_url="https://api.deepseek.com")

resp = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[
        {"role": "system",
         "content": '从简历文本提取信息，输出JSON，字段：name(str), years(int), skills(list[str])。'},
        {"role": "user", "content": "张三，8年Java开发经验，熟悉Spring、MySQL、Redis。"},
    ],
    response_format={"type": "json_object"},
    temperature=0,
)
data = json.loads(resp.choices[0].message.content)
print(data)
```

注意：用 JSON mode 时 **prompt 里必须出现"JSON"字样并描述字段**，否则部分 API 报错或输出空对象。

### 2.5 更强的一档：json_schema 严格模式

`{"type": "json_object"}` 只保证"是合法 JSON"，不保证"字段对得上"。更强的一档是 `json_schema` 严格模式，由服务端约束解码过程，**保证输出严格符合你给的 schema**：

```python
resp = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[{"role": "user", "content": "张三，8年Java开发经验，熟悉Spring、MySQL、Redis。"}],
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "resume",
            "strict": True,
            "schema": {
                "type": "object",
                "properties": {
                    "name": {"type": "string"},
                    "years": {"type": "integer"},
                    "skills": {"type": "array", "items": {"type": "string"}},
                },
                "required": ["name", "years", "skills"],
                "additionalProperties": False,   # strict 模式必须显式声明
            },
        },
    },
)
```

严格模式的常见限制：所有对象都要 `additionalProperties: false`、`required` 要列全、不支持递归 schema、不支持 `minimum`/`maxLength` 这类数值和长度约束。**所以"服务端保证结构 + 客户端 pydantic 校验业务规则"是互补的，不是重复的**——年限必须 0~50、技能至少一项这类约束，只能靠 pydantic。

各厂商对 `json_schema` 的支持程度仍不一致（Ollama 本地端点尤其），**客户端校验永远不能省**。写通用封装时：先试 `json_schema`，收到 400 就降级到 `json_object`，最后一定过一遍 pydantic。

### 3. 用 pydantic 定义 schema 并校验

pydantic（前置知识：[[dataclass与pydantic]]、[[类型注解与typing]]）是 Python 世界的"Bean Validation"：

```python
from pydantic import BaseModel, Field, ValidationError

class Resume(BaseModel):
    name: str
    years: int = Field(ge=0, le=50, description="工作年限")
    skills: list[str] = Field(min_length=1)

try:
    resume = Resume.model_validate_json(resp.choices[0].message.content)
    print(resume.name, resume.years, resume.skills)   # 类型安全，IDE 有补全
except ValidationError as e:
    print("校验失败:", e)   # 进入重试流程，见下节
```

技巧：用 `Resume.model_json_schema()` 生成 JSON Schema 塞进 system prompt，模型看到精确 schema 后遵循度更高。

### 4. 失败重试策略

LLM 输出是概率性的，解析/校验失败是**常态而非异常**，必须设计重试：

```python
def extract_resume(text: str, max_retries: int = 3) -> Resume:
    messages = [
        {"role": "system",
         "content": f"提取简历信息，输出JSON，符合此Schema：\n{Resume.model_json_schema()}"},
        {"role": "user", "content": text},
    ]
    for attempt in range(max_retries):
        resp = client.chat.completions.create(
            model="deepseek-v4-flash", messages=messages,
            response_format={"type": "json_object"}, temperature=0,
        )
        raw = resp.choices[0].message.content
        try:
            return Resume.model_validate_json(raw)
        except ValidationError as e:
            # 把错误喂回去让模型自己改，比盲目重跑有效
            messages.append({"role": "assistant", "content": raw})
            messages.append({"role": "user",
                             "content": f"输出未通过校验：{e}。请修正后重新输出JSON。"})
    raise RuntimeError(f"结构化输出失败，已重试 {max_retries} 次")
```

要点：temperature=0 降低波动（见 [[采样参数详解]]）；把 `ValidationError` 回传给模型"自我修复"；重试仍失败要有兜底（降级/人工/报错），不能死循环。

**成本意识**：每次重试都把越来越长的 messages 重发一遍，第 3 次重试的输入可能是第 1 次的 3 倍。所以 `max_retries` 要有硬上限（3 次足够），并把重试次数打进日志——**"结构化输出重试率"是一个该报警的指标**：它突然上涨通常意味着上游偷偷换了模型版本，或者你的 prompt 被改坏了（见 [[Token与上下文窗口]] 的 usage 监控）。

### 5. 与流式的取舍

JSON 没接收完就是不合法的，所以**结构化输出一般不做流式**（见 [[流式输出与SSE]]）。确需边生成边展示时，可用增量 JSON 解析库或"先流式给人看、后台再出结构化结果"的双通道方案。
